# Runner R5 — мастерская и производство

R5 добавляет постоянный заработок в общий серверный кошелёк. Мастерская доступна из галереи, результатов и безопасного магазина. Покупки и ручные нажатия запрещены во время боя и подготовки к нему; выход возвращает в исходный безопасный экран. Производства работают в меню, магазине, бою и при закрытом приложении. Никакие убийства, компоненты или дистанция офлайн не выдаются.

## Принятый начальный баланс

Новый аккаунт начинает с нулевого золота и без производств; имущество существующих аккаунтов сохраняется. Нажатие даёт 1 золото. Три улучшения нажатия стоят 100/500/2500 золота и заменяют доход на 2/4/8 золота. Организация мастерской стоит 1000/10000/100000 золота и заменяет общий множитель на 1,25/1,5/2.

| Производство | Первая цена, золото | Доход, золото/с |
| --- | ---: | ---: |
| Подмастерье (`apprentice`) | 25 | 0,05 |
| Плавильня (`smelter`) | 250 | 0,6 |
| Золотой пресс (`press`) | 2500 | 7 |
| Алхимическая линия (`alchemy`) | 25000 | 80 |

Цена следующей единицы — `ceil(baseGold × (1180/1000)^owned)` целого золота. Округление выполняется один раз по точной рациональной величине; первые цены подмастерья — 25/30/35/42/49/58. Цена, которая не помещается в кошелёк, возвращается как `null`; покупка отклоняется с `PRODUCTION_PRICE_OVERFLOW`. Престиж и сброс не добавлены.

Все числа мастерской и рецепт Часов доступны в действующем редакторе баланса. Базовая цена производства должна содержать целое золото. Базовые ставки выражены целыми goldMilli в секунду; организация — целым множителем ×1000. Числовые границы относятся к поддерживаемому типу хранения и проверяются сервером и конструктором.

## Время, история и точность

Сервер использует UTC-время; клиент не передаёт длительность, ставку, цену или сумму дохода. Ставка равна сумме `owned × rateGoldMilliPerSecond`, умноженной на коэффициент организации текущего уровня. Расчёты — BigInt. После умножения на миллисекунды и коэффициент ×1000 остаток хранится с постоянным знаменателем 1000000 от goldMilli; повторные короткие начисления не теряют дроби.

При начислении интервал начинается в `settledAtMs`. Политика офлайн лимита берётся из ревизии, действовавшей в начале интервала: по умолчанию учитываются его первые восемь часов. Этот один лимит действует на весь интервал, даже если за время отсутствия вышло несколько ревизий. Сервер разбивает только учитываемый интервал по реальным UTC-меткам публикаций и применяет ставки, действовавшие в каждой части. Маркер затем передвигается на всё текущее время, включая отброшенный остаток; повторный запрос не возвращает пропущенные часы. При откате часов маркер не уменьшается. Регулярные начисления во время активности не создают восьмичасовой суточный лимит.

Настройки мастерской действуют сразу после публикации. Публикации в одну миллисекунду упорядочены неизменяемым EAV-параметром `publication-order`; время не подменяется будущим значением. Публикация при регрессе серверного UTC-времени отклоняется. Цена/доход нажатия используются из текущей ревизии. Боевые правила, предметные рецепты и эффект Часов закрепляются в начатом забеге и меняются со следующего забега.

Перед каждой покупкой или улучшением сервер в одной транзакции начисляет прежний доход, проверяет профиль/котировку, списывает золото и изменяет количество/уровень. Новое производство не получает доход за прошедшее время.

## Часы должника

`debt_clock` — талисман для всех героев, один уровень, рецепт 450 золота + 3 жара + 1 ядро. Модификаторов боя нет. На каждое десятое подтверждённое сервером убийство в забеге выдаётся 30 секунд текущего производства. Частота и число секунд закреплены в балансе забега, ставка производства берётся из действующей мастерской в момент обработки серверного убийства. Счётчик — подтверждённые уникальные враги этого забега; новый забег начинается с нуля. Повтор врага/операции не выдаёт бонус. Бонус добавляет золото и дробный остаток, не перемещая обычный маркер начисления. Старые забеги без этого эффекта сохраняются и восстанавливаются, даже если аккаунт уже владеет новым талисманом.

## API

Полный машинный контракт находится в [OpenAPI](../contracts/openapi.json).

`GET /api/v1/workshop` требует сессию, возвращает сохранённые количества, уровни, текущие серверные котировки и время без начисления или изменения revision. `workshop` добавлен в результат новой операции; исторический receipt может не содержать этого поля.

Через существующий `POST /api/v1/operations` с `operationId`, `expectedRevision`, `clientId`, сессией и CSRF:

| Тип | payload | Результат |
| --- | --- | --- |
| `forge_settle` | `{}` | Начислить пассивный доход; допускается во всех фазах |
| `forge_tap` | `{balanceRevision}` | Одно ручное нажатие |
| `forge_buy` | `{productionId,balanceRevision}` | Купить одну единицу производства |
| `forge_upgrade` | `{upgrade:"tap" или "organization",balanceRevision}` | Купить следующий постоянный уровень |

`lastSettlement` присутствует только в результате совершённого начисления, не в GET. `productionRate.numerator/1000` — goldMilli/с. Покупка/нажатие по устаревшей котировке возвращает `BALANCE_REVISION_CONFLICT` (409) и полностью откатывает начисление и расход; клиент получает актуальные данные перед новой попыткой. Повтор того же operationId/тела возвращает прежний receipt, изменённое тело — `OPERATION_CONFLICT`. Параллельные расходы одной revision могут завершить только одну операцию. Профиль выбирается из сессии.

## Переход и проверка

Для первого выпуска R5 нужна парная новая сборка сервера и frontend. Перед 006 остановить все прежние процессы записи, сделать и проверить PostgreSQL 18 backup, затем применить `db:migrate` владельцем схемы, выполнить `src/profile/runtime-grants.sql`, запустить новый сервер и проверить `/readyz`. Прежние миграции 001–005 не изменяются. 006 сохраняет боевые значения действующей ревизии, кошелёк, компоненты, предметы, stats, receipts и закреплённые забеги. Старый писатель после 006 блокируется протоколом `foxy.forge_writer`; возврат к старому executable без восстановления схемы/копии не является безопасным откатом. После установки R5 будущие изменения чисел через редактор не требуют перезапуска стенда или нового приложения.

Авторские проверки: `npm test` (экономика, API, обычные игровые сценарии, LastThrone integration), `npm run validate:content` (включая неизменность 005 и точное соответствие 006 генератору), `npm run test:db` на отдельной PostgreSQL 18 с настоящими средствами dump/restore. Независимая QA и AppSec проверяют конкретную ревизию отдельно. Успешная локальная проверка не означает применение на VPS.
