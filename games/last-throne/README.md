# Последний трон — R3

Текущее обновление камеры — `r3-content-002`: утверждённый более близкий ракурс с углом около 35°, кадрирование игрового поля и целый Древний справа. Это обновление клиента при прежних core/content/save4/API; exact `r3-001` сохранён для отката. На существующем R3 сервере `content r3-content-002` оставляет API `r3-001` и runtime-контейнер работающими. Canonical assembler и режим `camera-r3` описаны в backend `deploy/last-throne/README.md`; в готовом пакете этот helper находится в `repository-integration/backend/`.

После переключения launcher новая партия открывает новый ракурс. Продолжение старой партии по прежнему контракту использует закреплённый exact клиент, включая прежнюю камеру; открытые вкладки автоматически не заменяются.

Браузерная tower defence в мире Доты: три линии, 15 волн и пять героев — Pudge, Undying, Rubick, Shadow Shaman, Sniper. Защита: баллиста, магическая башня, тотем замедления. Квадратные фундаменты зданий и круглые позиции героев различаются; цена и preview показываются до подтверждения. Командиры волн5/10/15 выполняют осаду, обход и магическое усиление.

В подготовке можно отправить одного героя в лагерь за золотом, тайную лавку за выбором предмета или к Рошану за Aegis. Герой отсутствует в обороне, его позиция зарезервирована; время идёт только в бою. Два слота предметов дают дополнительную цель, ускорение атаки, обнаружение скрытых врагов или лечебную ауру. Награда лавки требует явного выбора/замены либо отказа и не пропадает при заполненных слотах. Aegis хранится отдельно и один раз автоматически возвращает своего героя с полным HP.

Undying поднимает надгробие и временных зомби; Rubick крадёт последнее реально использованное заклинание командира и применяет лечение/удар/щит; Sniper готовит прицельный выстрел. Модели, магия и новые звуковые сигналы локальные, чужих игровых ассетов нет. Баланс и субъективное качество требуют плейтеста.

Профиль гостевой, привязан к браузеру. IndexedDB и облачные межволновые контрольные точки хранят вылазку, предметы, ожидающий выбор и Aegis. Reload посреди боя возвращает к объявленной контрольной точке. Результат client_reported: сервер не пересчитывает бой для защиты от подмены. R1 продолжается на exact r1-002 с5волнами/save2, R2 — exact r2-001 с10волнами/save3. R3 использует save4; старые партии не конвертируются.

## Запуск

Нужны Node.js24 и npm:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173/td/. Dev создаёт immutable r3-dev-<timestamp>, persistent PGlite в .local/database и хранит сборки в .local/releases. Это локальная разработка; production использует отдельную PostgreSQL17. Авторитетное хранение — scalar typed EAV, новые миграции аддитивны;001–006 неизменны.

Готовая поставка содержит releases/r3-content-002, exact r3-001/r2-001/r1-002/r0-002 и production-зависимости. Запуск готового клиента:

```sh
RELEASE_ID=r3-content-002 DEV_RELEASES_DIR=releases npm run dev
```

Проверки:

```sh
npm run typecheck
npm test
npm run test:browser
```

Для browser check нужен Chromium Playwright либо BROWSER_EXECUTABLE_PATH. Доступный Linux/Chromium/SwiftShader стенд не подтверждает FPS физического ПК.

## Размещение и обновление

Сервер общий с первой игрой. Namespace /td, отдельные каталоги/БД/API и стабильный gateway с A/B-процессами. R2→R3 выполняется аддитивной миграцией и switch дочернего API без пересоздания существующего runtime-контейнера. Для совместимости старого verifier новый R3 клиент включён точным ID; будущий content-only ID необходимо заранее разрешить в манифесте API. Откат frontend_only сохраняет R3 API для save4. Pair rollback к R2 после появления R3 данных запрещён.

Первая установка либо переход старого технического runtime R0/R1 — отдельная процедура. Установка R3 на VPS в этой сессии не выполнялась: нет серверного канала. Первая игра и актуальные модели общего хаба сохраняются.

Основание и точные правила: docs/R3-CONTRACT.md и docs/Last-Throne-TZ-v0.6.md. Инструкции и доказательства итоговой сборки перечислены в TASK_STATE.md. Исторические документы R0/R1/R2 относятся к своим сборкам.
