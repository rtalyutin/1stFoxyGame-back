# Frontend R2

R2 клиент работает только с r2-core-1/r2-meta-1/save3 и проверяет hash опубликованной EAV-проекции. Babylon.js 9.29.0 рисует поле, HTML содержит карточки и доступные действия. Круги предназначены героям, квадратные фундаменты зданиям. Кнопка «Площадки» открывает список фундаментов для клавиатуры; цена и призрачный preview предшествуют подтверждению.

Пять карточек и горячие клавиши1–5. Q — выбранная способность, T — перенос; способности доступны в бою. Undying выбирает область надгробия, Sniper конкретного врага и приоритет автоатак. Пустой слот Rubick выбирает командира с последним доступным заклинанием, заполненный — область применения. Карточка показывает название слота и отдельные кулдауны. Клавиатурные быстрые точки включают область вокруг самого героя. Таймеры, цель и результат принадлежат ядру.

В меню перечислены активные локальные и облачные партии обоих релизов. Ссылка R1 ведёт к его точному сохранённому клиенту; R1 никогда не преобразуется в десять волн. IndexedDB и guest cookie общие в namespace /td, а незавершённое создание R2 отделено sessionStorage ключом с releaseId. Клиент сохраняет checkpoint перед волной и после неё; mid-wave reload возвращает эту границу. SaveManager остаётся общим протоколом pending/revision/branch и использует schemaVersion из закреплённых pins.

Единственный requestAnimationFrame и фиксированные30тактов/сек; фон и потеря WebGLконтекста ставят партию на паузу, накопленное время отбрасывается. Восстановление требует явного продолжения. WebGL2 проверяется до создания партии, scene.ready() до loop; ошибка показана с сохранной контрольной точкой. Ключи focus сохранены при обновлении панелей; числовые таймеры не заменяют focus intent.

Readonly lastThroneDiagnostics возвращает копии состояния/событий и ограниченные счётчики. Команды/изменение состояния через него не доступны. Это инструмент поддержки и конкретной приёмки, не доказательство пользовательской понятности или FPS на физическом GPU.
