# Независимая приёмка R0

Итог: проверенные локальные SQL/API/доставочные сценарии — PASS; все три найденных дефекта исправлены и независимо перепроверены. Полная эксплуатационная приёмка остаётся BLOCKED: Unix socket, контейнеры и целевой VPS недоступны для проверки. Это не разрешение на установку или публикацию.

## Объект и границы

Проверяющий: отдельный агент `spec_verifier`, не автор реализации. Входы: `Last-Throne-TZ-v0.2.md`, `docs/R0.md`, `README.md`, `ops/RUNBOOK.md`. Предмет: технический R0, типизированный EAV, read-only API, неизменяемые клиентские релизы, локальные A/B-процессы и восстановление постоянного gateway. Игровые правила, гостевые профили, checkpoint/finish R1 не входят в эту приёмку.

Среда: Node v24.19.0, PGlite, реальные дочерние Node-процессы и loopback HTTP. Секреты и сервисы VPS не использовались. Независимые runtime-пробы используют синтетические артефакты и отдельные временные каталоги, без production-БД.

## Найденные дефекты

### QA-01 — допустимый код параметра ломает runtime-проекцию

В опубликованной схеме создать параметр `code='constructor', data_type='text', multiple=true`; записать `first`/`second` с ordinal 0/1 и опубликовать release. SQL принимает валидные записи, но `readContent()` первоначально завершался ошибкой `parameters[row.parameter_code].push is not a function`: объект параметров наследовал `Object.prototype.constructor`.

Исправление автора: словарь без прототипа в `db/content.mjs`. Независимый повтор вернул `[{ordinal:0,value:'first'},{ordinal:1,value:'second'}]`. Исходный reproducer: `node /tmp/td-independent-eav.mjs`, отдельная свежая PGlite-БД. Проверка не использует ожидаемый результат из реализации: oracle — исходные две типизированные строки и их ordinals.

### QA-02 — оборванное тело upstream не закрывает downstream

Синтетический API отвечает `Content-Length: 100`, пишет один байт `{` и через 30 мс закрывает свой сокет. Вызов через реальный gateway не завершается ошибкой транспорта; `fetch().text()` прекращается лишь по собственному `AbortSignal.timeout(600)`, с `TimeoutError`. При этом activeRequests уже равен нулю и следующий запрос version проходит.

Исправление автора: обработка error/aborted/преждевременного close ответа upstream с закрытием downstream и однократным завершением счётчика. Независимый повтор `node /tmp/td-independent-runtime.mjs` дал `TypeError` чтения тела до клиентского таймаута, отсутствие uncaught exception, active=0 и HTTP 200 на последующий version. Постоянный регрессионный тест: `a truncated upstream response immediately closes the client stream and leaves the gateway alive` в `tests/delivery.test.mjs`. Это отказ локального fixture, не измерение production-сети.

### QA-03 — незакоммиченный content promotion выполняется при recovery

После успешной установки A начать `content B`. На hook фазы `verified`, до `saveSelection`, сохранить фактический журнал и прежние selection/current. В отдельном state-каталоге запустить новый Supervisor из этого снимка. Это детерминированная модель состояния файлов после внезапного обрыва на данной границе; процесс production не прерывался.

Ожидание: остаётся клиент A, поскольку selection.operationId принадлежит предыдущей операции. До исправления pointer становился B: совпадение `targetApi` с выбранным API не доказывало commit при content/frontend-only, где API не меняется. Исправление автора: recovery требует совпадения durable operationId. Независимый повтор `node /tmp/td-independent-recovery.mjs` оставил `r0-qa-a`, как ожидалось. Постоянные регрессионные тесты `cold recovery honors the operation commit ...` в `tests/delivery.test.mjs` различают precommit и committed фазы для content и frontend-only rollback.

Исходные независимые reproducer-файлы находятся во временной среде проверки; сценарии и наблюдения сохранены выше. В поставляемых тестах сохранены регрессии всех трёх дефектов. Для адресного повторения после будущей правки:

```sh
node --test --test-name-pattern='constructor|truncated upstream|cold recovery' tests/*.test.mjs
```

Отфильтрованный повтор не заменяет полный discovery/прогон `npm test`.

## Блокировки внешней приёмки

- Unix socket/CLI: обязательная интеграционная проверка пропущена по `EPERM`; constructor-only harness не заменяет её.
- Docker/Compose, реальный Nginx/TLS, container ID/StartedAt, постоянные volumes и восстановление контейнера: локально не исполнялись.
- VPS первой игры, ресурсный запас A+B+PostgreSQL, её маршруты и реальные пользовательские сценарии: не проверялись.
- Многосессионная конкуренция PostgreSQL, backup/restore и реальные инфраструктурные миграции: PGlite этого не доказывает.
- Браузерный smoke окончательного `r0-002` выполнен root на Chromium `153.0.8010.0` из npm-пакета, с sourceHash `62ab2127e3c88f1d76b530beb9e7d4e34b44a1df531b07d748a9573290e6227a`, совпадающим с проверенным manifest. Прочитан `docs/browser-report.json`: семь проверок PASS, pageErrors пуст. Исполнены связь с реальными API/EAV, движение кольца и отключение анимации при reduced motion, ошибка/повтор, отсутствие горизонтального переполнения на 390px, недоступный pointer/release и восстановление launcher. Скриншоты окончательного пакета получены root. Это отдельное свидетельство исполнителя root, а не самостоятельный браузерный прогон spec_verifier.

Открытых дефектов в выполненной локальной области после перепроверки не осталось. Локальные исполняемые gates: PASS. Полный эксплуатационный gate и установка на VPS: BLOCKED по перечисленным отсутствующим свидетельствам. `evidence_status=VERIFIED` относится только к названным локальным сценариям; `action_decision=CONTINUE` означает передачу root для сборки и проверки артефакта, не разрешение внешнего выпуска. `return_to=root`.

Формат передачи: `FEATURE_HANDOFF/1`; SHA-256 контракта `880ed9d2dc0004f39250f4a5c3739840cc1f9c4b37edf78b652dc787f5aa44e4`.
